Local AI Harness for Coding Agents

Install, update and switch local LLM engines and models.

Run a coding agent on a local LLM, on whatever hardware you have. No API key, and your code stays on your machine. It installs and switches halogen, Strata, gufo, osmos, CIRU and strix-llama.cpp itself, and connects to llama.cpp, vLLM, Ollama, LM Studio or a cloud model. On AMD Strix Halo (Ryzen AI Max+ 395) it runs a 125B Qwen3.8 Flash-Next on the iGPU with 262k context, while NPU models screen and route prompts and a sidecar writes commits and summaries. Built on pi.

Source on GitHub · Releases · Windows setup (beta) · Local vs cloud comparison

What you get

  • Install: detects your hardware, recommends an engine and model, then installs, starts and tunes it.
  • Update: checks for new engine releases; halogen, Strata, gufo, osmos and strix-llama.cpp upgrade from the menu and roll back if the new version fails its checks.
  • Switch: ten engines or a cloud model, stock or abliterated weights, one menu, limits re-sized on every switch.
  • Plus: crash recovery, NPU side jobs (prompt triage in about 120 ms, near-duplicate file scans), token-saving extensions and symbol-precise code tools.
  • Logged benchmarks for engines and models.

Why not just Ollama or LM Studio?

Ollama and LM Studio each run models in their own engine. This harness installs and upgrades the engines tuned for your hardware (halogen, Strata, gufo, osmos, CIRU, strix-llama.cpp), switches between them and any Ollama, LM Studio, vLLM or llama.cpp you already run, and re-sizes the coding agent's limits for each engine and model. Keep Ollama: it is one of the engines you can switch to.

Install on Linux

Needs pi and uv. Setup asks every question first and installs nothing until you confirm.

git clone https://github.com/aic0d3r/local-ai-harness && cd local-ai-harness
./harness setup             # detects your hardware, asks for a model, installs and starts its engine
./start.sh ~/my-project     # opens the coding agent on your project
